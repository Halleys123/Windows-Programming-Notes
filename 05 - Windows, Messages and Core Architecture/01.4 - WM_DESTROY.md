`WM_DESTROY` is sent to the window when it starts to be destroyed. In this stage, in opposition to `WM_CLOSE`, you cannot stop the process, you can only make any necessary cleanup. When you catch `WM_DESTROY`, none of its child windows have been destroyed yet.

In this stage you first cleanup the memory and save files that may be necessary and after that use `PostQuitMessage` function to insert [[01.5 - WM_QUIT|WM_QUIT]] message in the Queue that is used to indicate to our program that we should now quit exit the [[01 - Core architectural overview#Message Queue and Loop|Message Loop]].
